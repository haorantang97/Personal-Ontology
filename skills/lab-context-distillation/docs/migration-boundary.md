# 独立实现与迁移边界

## v2 差额迁移

源蒸馏任务升级到 v2 时从已验收 Map 之后开始，不重建、不重投 Map。
复用冻结的脱敏 episode / evidence 权威文件及其回执，从各领域高召回路由开始，
要求每条 route 恰有一个处理结果、同一 episode 的零到多个独立事件各自保留语义
状态，并用逐 route evidence/place 白名单阻止跨路由注入；随后分别为旅行、教育、工作、关系、
居住、家庭、健康、财务、创作生成覆盖回执。

旅行领域旧结果只有在校验哈希、分母、事件多重性、事件状态和双白名单迁移后，
才能作为已完成领域输入；不需要重跑 Map，但不能把旧单对象结果直接视为当前
契约。其他领域只做差额。等各领域覆盖状态明确后，再合并完整人生
账本，重建 biography、自我模型、voice/advisor 资产、运行时索引和 QA。旧结果
全程只读保留，迁移过程不得写入知识库。

## 允许迁移的内容

- 聚合后的事故类型、验收原则、状态机不变量和测试意图；
- 公开且许可兼容的通用协议知识；
- Python、SQLite 和可选 SQLCipher 的公开接口；
- 完全新写的规范、数据契约、实现和合成 fixture。

## 禁止迁移的内容

- 任何真实聊天、联系人、身份映射、密钥、源库或私密路径；
- 旧任务的 release、账本、断点、自动化、回执和运行状态；
- 旧工作区的 prompt、schema 文本、脚本、测试实现和实验版本；
- 受限微信解析工具的源码、逐行改写、翻译或重新包装；
- 以旧工作区为运行依赖的软链接、导入路径或运行时读取。

## 原任务保护

新 Skill 只能在自身 case 目录和用户明确指定的输入副本上工作。任何源数据库操作均只读，并先产生一致快照。新实现不得启动、暂停、迁移或修改旧任务。旧任务额度恢复后，应能按其原账本和断点直接续跑。

## 发布前边界检查

发布候选必须扫描真实姓名、聊天文本、密钥模式、绝对私密路径、旧任务 ID、旧工作区实验标识和未声明第三方代码。扫描有命中就阻断打包，除非命中位于本文件对“禁止项”的抽象描述中且不含具体私密值。
