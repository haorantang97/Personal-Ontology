# Clean-room 独立实现声明

## 实现来源

本项目从行为需求、完整对话的聚合事故类型、公开接口和平台目录/表名的事实线索出发，先写设计与失败测试，再编写全新的模块、数据契约和 CLI。所有 fixture、身份、消息和媒体都由本项目独立合成。

新一代设计又机械对账了上一次封装之后的 66 轮新增对话（内部轮次 816–881），与既有 45 类事故合并去重。公开包只保留 74 类聚合规则与测试映射，不保留对话正文、身份或私密运行回执。

## 明确排除

- 未复制、逐行改写、翻译或重新包装任何受限微信解析源码；
- 未导入旧工作区脚本、prompt、schema 文本、release、账本、断点、回执或自动化；
- 未把真实聊天、身份、密钥、私密路径或实验版本放入包中；
- 未把旧工作区作为运行时依赖，也未使用软链接连接它。

## 允许的基础

实现使用 Python 标准库、SQLite 的公开接口和可选外部 SQLCipher 进程协议。第三方代码没有 vendoring 到本仓库。许可状态见 `THIRD_PARTY_NOTICES.md`。

## 证据链

1. 独立设计规范和迁移边界；
2. 聚合的公开经验，不含原文；
3. 先失败、后通过的合成回归测试；
4. 全新命名的数据契约、状态机、schema profile 和实现；
5. 发布前隐私、路径、秘密和第三方 notice 扫描；
6. 真实平台与跨模型环节明确标成待实战验证；
7. 进程内存取 key、注入、重签名、私有 key derivation 和被下架工具包装被明确排除；
8. 仓库外独立进程跑通两平台合成 CLI 前向链路。
9. 外部参考只记录抽象能力与拒绝项，不 clone、vendor、导入或建立兼容依赖；无许可和 GPL 参考严格限于思想层。
10. v1 基线与 v2 契约/发布都用 Git commit、tree 和清单哈希独立冻结，新版不改写旧版。

Nuwa、digital-life 和 me.skill 在审阅时显示 MIT，本项目仍只采用跨领域/holdout/非泛化验证、可携带资产包、分层与纠正回滚等抽象方法，没有复制其代码、提示词、模板、目录或措辞。Persona-Skill 审阅时未见许可，PersonalOS 是 GPL-3.0，Nova 未作为工程来源；三者都只作为抽象思想参考。详见 `references/external-method-review.md`。

此声明描述工程流程，不构成法律意见。正式公开发布前应进行律师和代码来源复核。
