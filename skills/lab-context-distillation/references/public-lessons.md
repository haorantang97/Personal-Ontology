# 从长周期蒸馏中聚合出的公开经验

本页只保留通用经验，不含任何聊天正文、人物、路径、密钥、回执或旧实验实现。

1. 数据总数相等不能证明完整，逐行 fingerprint 才能发现漏行、重复和错归。
2. “发出”不等于“创作、说过或认同”，引用、转发和作者必须拆开。
3. 结构合规不等于内容可靠，精确率和召回率要分别验收。
4. 少量场景容易产生讨喜但片面的性格结论，必须找反例、局限、代价和时间变化。
5. 传输 schema 是兼容层，本地完整 validator 才是权威。
6. 日期、null、排序和 evidence 关系等结构问题优先确定性修复，但修复不能改含义。
7. 基础设施失败和内容失败必须隔离，否则会重跑有效结果或错误降低全局并发。
8. accepted、release、candidate set 和 receipt 必须不可变；规则变化走新 generation。
9. 大任务要按记录和事件边界拆分；紧凑视图是派生物，不能覆盖完整 Map。
10. 进度必须写清阶段、分母和状态；计划单元、云调用、活跃任务和本地积压不是一个数字。
11. 对话是否仍在进行不应决定任务正确性；持久账本和租约让工作可恢复。
12. 知识库是批准后的输出层，不是蒸馏目标本身。
13. 保守摘要不能代替完整事件账；重要性只决定展示，不决定是否保留。
14. 每条冻结 route 要有且仅有一个处理结果；它可产生零到多个独立事件，无信号也是明确结果。
15. 消息时间和事件时间是两种证据，必须分开并保留精度。
16. 领域覆盖要独立报告；“未提取”不能说成“用户没有”。
17. 地点 alias 和归属只是候选；唯一确定映射才自动应用，歧义应保留。
18. 中文检索不能仅按空格拆词，无命中也不能用不相关前 N 条填充。
19. biography、voice 和 advisor 权限不同；体现语气不等于允许冒充、发送或承诺。
20. 自我模型要区分观察、模式、假设和建议；矛盾可能是时间或领域信号，不应自动抹平。
21. 只有会改变 Agent 行为的少数问题需用户校准；其余留在安全层。
22. 知识卡是高可信索引，不是全部证据；不晋升为卡不等于删除。
23. 新增、纠正、撤回、领域重提取和回滚必须是正式状态迁移，而不是覆盖文件的操作建议。
24. 实战汇总数字、合成测试和真实设备验证是三种不同证据，不能互相替代。
25. route 的处理状态不能替代 event 的语义状态；同一 episode 里的完成与计划等事件要各自保留。
26. evidence 和 place ID 都必须来自自己 route 的冻结白名单；ID 看似有效也不能跨 route 借用。
