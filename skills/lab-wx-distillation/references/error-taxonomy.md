# 错误分类与处理

| 类别 | 例子 | 默认动作 |
|---|---|---|
| 基础设施 | 超时、429、5xx、进程中断、未知传输事件 | 先查有效输出，再带回退重试；系统性错误才调低并发 |
| 结构 | 日期/null、字段形状、重复 evidence id | 运行白名单修复并复验；保留 before/after receipt |
| 内容 | 缺证据、错误归因、夸大、漏关键反例 | 隔离单元或交人工；不影响其他独立单元并发 |
| 隐私 | 秘密、身份或未脱敏原文进入 release | 立即阻断；回到本机脱敏层 |
| 依赖 | Merge/Final 前置 stage 未 accepted | 等待依赖 receipt；不要重试模型 |

真实 payload 前先做无数据传输探针。提交前检查 prompt 存在、非空、大小合规、payload 只绑定一次、packet seal 正确。接口返回未知事件时，先检查输出制品，不要仅凭事件名判失败。

若 canary 出现系统性拒绝（例如连续样本全部失败），立刻停止扩大范围，用最小样本定位，不要继续全量验证。
