# 蒸馏全路径：聊天记录怎样变成“更懂你的说明书”

这套方法不是把聊天记录丢给 AI，让它随口总结你是什么人。它更像一条有质检、有封条、能追溯的整理流水线。

## 第一步：资料留在本机

先在你的电脑上找到你明确允许处理的聊天资料。系统会把同一个账号的消息、联系人、群聊和附件目录一起登记，但真实路径只留在本机。随后做一份只读快照；如果记录正在变化，系统会重新来过，不拿一半新、一半旧的副本继续。原文件始终不动。

若资料需要解锁，公开版本只接受你已经依法取得并单独授权使用的密钥。密钥只在本机临时使用，不写进日志，也不交给 AI。它不会从微信进程里扫描密钥，也不会注入或修改微信；这类做法存在明确的法律和平台规则风险。

## 第二步：把不同聊天整理成同一种记录

每条消息都有自己的编号。本人写的话、回复里引用的话、别人转发来的内容，会分开放。联系人、群成员、图片、语音、文件、可读取的收藏和朋友圈也会分别登记。找不到的媒体会计入“本来应该有多少、实际找到多少”的缺口，而不是悄悄略过。即使两句话一模一样，也不会擅自删掉，因为它们可能发生在不同时间、不同情境。

## 第三步：先脱敏，再让 AI 看

邮箱、电话、链接、常见密钥和人物标识先在本机遮掉。原始数据库、密钥和“谁是谁”的对照表不会发给 AI。只有通过检查的脱敏副本，才进入下一步。

## 第四步：贴上“数字封条”

系统会给这批资料计算一个哈希。可以把哈希理解成数字封条：文件只要改了一个字，封条就对不上。封好以后，这一版不能偷偷修改；要改规则或补资料，就新建一版。

## 第五步：先做全量 Map

AI 分批阅读脱敏资料，把可能有价值的观察标出来，并附上证据编号。它看的不只是履历，还包括：你怎样表达、怎样做决定、重视什么、在压力下怎样行动、哪些模式会带来收益或代价、有没有反例、这些习惯是否随时间变化。

每一批都要经过本机质检。每条输入要么被证据引用，要么说明为什么排除。空值、重复编号这类不改变意思的小问题可以自动修；涉及含义、证据归属或人物判断的问题，不能让程序自作主张。

## 第六步：九个领域，一本完整人生账

聊天里的事会分到旅行、教育、工作、关系、居住、家庭、健康、财务和创作九个领域。每个领域都有自己的完整清单，每件事必须有一个明确去向：已发生、已完成、进行中、预订未确认、签证、计划、讨论、第三方、非本领域、证据不足或没有信号。不能只写“看过了”。

这本账不会因为一件事“不够重要”就删掉它。重要性只决定哪些事在主时间线上更显眼。某个领域还没做，就标成“未提取”，不能说成“你没有这段经历”。

## 第七步：把“聊天时间”和“事情时间”分开

一条今天发的消息，可能说的是去年的事，也可能只说“之后”。系统同时保存消息被看到的时间和它声称的事件时间，并标注精确到日、月、年，还是只有相对说法。不知道就留空，不拿发送日期顶替。

## 第八步：地点不猜

国家、城市、次区域、地标和其他地点分开保存。简称、错别字、俗称和“某地属于某地”先只做候选。只有唯一而且肯定安全的对应才自动采用；有歧义就保留“待定”。“去过的国家”里只放国家，城市和地标仍留在事件账中。

## 第九步：把跨时间的事连起来

各领域完成后，再找重复、因果、冲突、变化和缺口。原来的完整 Map 和事件账一直保留；为超大任务做的“紧凑版”只是带来源链的副本。过长文字可以分块，但必须能原样拼回，证明一个字都没丢。

## 第十步：形成不同用途的个人说明书

结果不是“你很认真”这类空话。它会分开：真实观察、有限规律、待验证猜想和行动建议。建议必须说清收益、代价、什么时候触发、能否撤回和有多不确定。反例、时间变化和不同领域的差异也要留下。

使用时有四种模式：人生经历、表达草稿、决策建议和混合。表达草稿会看关系远近、情绪温度、目的、长度、玩笑、粗口边界、怎样纠错和连发节奏，但只能起草，不能冒充本人、自动发送或替你承诺。

## 第十一步：只取这次真正需要的内容

运行时先按领域、时间、事情状态和地点筛选，再用对中文友好的方式查找。它只加载这个问题需要的最小私密上下文。没找到就说“不知道”或“这个领域还没提取完”，不拿前几条无关记录凑答案。

## 第十二步：独立质检和人工裁决

另一轮检查会专门找漏掉的证据、过度推断、被忽略的负面模式和反例，并把“说得对不对”和“漏得多不多”分开计算。还会独立检查：这些规律能否在其他领域复现，能否预测没见过的例子，是否只是对任何人都适用的套话。真人盲测没做过，就明确标“待做”。

身份不清、证据冲突或意义无法确定时，交给人决定，并留下新的数字封条。只有会真正改变 Agent 行为的少数问题才请你校准，不把一大堆抽象猜想丢给你判断。

## 第十三步：可以补、改、撤和回滚

以后新增资料，只处理新的部分。你纠正一个结论、撤回一个来源、重做某个领域或回到旧版时，系统都新建一版，不偷改旧结果。已经通过的 Map 不重跑；只重建被影响的领域和后续结果。

## 第十四步：知识库写入前再问一次

知识卡只是高可信的快速索引，不是全部记忆。没晋升为卡的低置信证据仍保留，也不会偷偷进入核心卡。系统先展示“准备写入什么”和数字封条；只有你明确批准后才产生写入许可，真正写入仍是单独一步。

整条路径最重要的原则是：原始秘密留在本机，AI 只看通过隐私门的脱敏资料；通过的结果不重复跑；所有变化都能追溯；不知道的地方明确说不知道。

目前，公开 Skill 的全路径已用完全虚构的 macOS 和 Windows 数据跑通。一次聊天片段可以记录多件互不覆盖的事：系统先给这条片段一个处理结果，再让每件事分别标记“已完成”“计划中”等状态。证据和地点还各有一份只属于这条片段的名单，名单外的编号进不了总账。

旅行方法另有不含私密内容的旧版实战汇总证据：1696/1696 条都得到处置，311/311 个地点完成规则检查，其中 42 个保留待定。它们仍需按新版结构做无损对账，不能直接当成新版已经实战验证。这也不等于公开代码已经跑过私密资料，更不证明所有微信小版本或其他八个领域已经实机验证。第一次实机使用仍要逐版本核对；对不上就停下，改用用户提供的合法导出。
